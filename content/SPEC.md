# 뿌리 카드 작성 규격

"뿌리"는 릴스처럼 위로 넘기는 어원 카드 앱이다. 한국어 사용자가 대상이다. 카드 한 장 = 한 줄짜리 놀라운 사실 + 관련 단어 몇 개 + (탭하면) 이유 한두 문장.
기존 카드 43장은 `/home/claude/content/existing.json`에 있다. 먼저 읽고 톤과 길이를 맞출 것. 기존 카드와 같은 사실을 다시 쓰지 말 것.

## 출력 파일
`/home/claude/content/batch_<번호>.json` 하나. 형식:

```json
{
  "cards": [
    {"id":"bd-window","e":"🪟","h":"window의 뜻은 ‘바람의 눈’","s":[["window","영어","/ˈwɪndoʊ/"],["vindauga","고대노르드어",""],["Fenster","독일어","/ˈfɛnstɐ/"]],"m":"고대 노르드어 vindr(바람)와 auga(눈)를 합친 말이에요. 독일어 Fenster는 라틴어 fenestra에서 왔어요.","v":"window"}
  ],
  "vocab": {
    "window": ["🪟","창문","window","Fenster","fenêtre","ventana",["窓","mado"],["窗户","chuānghu"]]
  }
}
```

## 카드 필드
- `id`: 배정된 접두사 + 소문자 영문 슬러그 (예: `bd-window`). 파일 안에서 유일.
- `e`: 이모지 1개. iOS/안드로이드에서 흔히 보이는 오래된 이모지만 (국기, 2022년 이후 이모지 금지).
- `h` (훅): 넘기다 멈추게 만드는 한 줄. 한국어 반말 평서문(‘~다’) 또는 짧은 질문. **공백 포함 24자 이내.** 단어 자체가 아니라 놀라움을 담을 것.
  - 좋은 예: "school의 원래 뜻은 ‘여가’였다", "보드카의 뜻은 ‘작은 물’", "father는 f, padre는 p. 왜일까?"
  - 나쁜 예: "사과는 여러 언어로 다르다"(놀라움 없음), "영어 apple과 독일어 Apfel은 인도유럽어족에서…"(너무 김)
- `s` (단어 줄): 2~4개(최대 5개). 각 항목 `[단어, 언어, 발음표기, 음성용텍스트(선택)]`. 훅을 뒷받침하는 단어만.
- `m` (설명): 탭하면 나오는 이유. 해요체 1~2문장, **75자 이내**. 훅의 ‘왜’를 답할 것.
- `v`: 이 카드가 다루는 일상어의 퀴즈용 어휘 id. 기존 어휘(existing.json의 `vocab`)나 이 파일 `vocab`에 반드시 존재해야 함.

## 언어 이름 (이 표기만 사용)
- 음성 재생 가능, 발음표기 **필수**: 영어, 독일어, 프랑스어, 스페인어, 이탈리아어, 포르투갈어, 러시아어, 네덜란드어, 일본어, 중국어, 아랍어, 튀르키예어
- 음성 없음, 발음표기 **빈 문자열 ""**: 한국어, 한자, 라틴어, 그리스어(고대), 산스크리트어, 고대영어, 고대노르드어, 산스크리트어, 페르시아어, 나와틀어 (그 밖의 사어·소수 언어도 여기 해당. 발음 ""로 둘 것)

## 발음 표기 규칙
- 유럽어: IPA를 슬래시로. 영어는 미국식, 스페인어는 스페인식(z, ce/ci = θ), 포르투갈어는 유럽식. 예: `/ˈwɑːtɚ/`, `/ˈvasɐ/`, `/manˈθana/`
- 러시아어·아랍어: 단어 칸은 로마자 표기(예: `voda`), 발음은 IPA, 4번째 칸에 원문자(예: `вода`)를 넣어 음성이 정확히 읽게 할 것.
- 일본어: 한자가 있으면 발음은 `"かな romaji"`, 4번째 칸에 가나(예: `["名前","일본어","なまえ namae","なまえ"]`). 가나뿐이면 발음은 로마자만(예: `["パン","일본어","pan"]`). 헵번식, 장음은 ā ī ū ē ō.
- 중국어: 간체자, 발음은 성조 표시 병음 (예: `kāfēi`).
- 한국어·한자·사어: 발음 `""`.

## 퀴즈 어휘 `vocab`
`id: [이모지, 한국어, 영어, 독일어, 프랑스어, 스페인어, [일본어, 로마자], [중국어, 병음]]`
- 그 언어에서 가장 흔한 일상 단어. 독일어 명사는 대문자, 프랑스어·스페인어는 관사 없이, 동사는 원형.
- 같은 단어가 기존 vocab에 있으면 새로 만들지 말고 그 id를 쓸 것.
- id는 영어 소문자 단어 (예: `window`, `eye`).

## 정확도 (가장 중요)
이 앱은 "뭔가 배웠다"가 핵심이라 틀린 사실 하나가 컨셉을 무너뜨린다.
- 어원 사전(Etymonline, Wiktionary, OED, 표준국어대사전) 다수설만 사실로 쓸 것. 확신이 없는 주장은 WebFetch로 `https://www.etymonline.com/word/<단어>` 또는 `https://en.wiktionary.org/wiki/<단어>`를 확인할 것.
- 학설이 갈리면 문장에 "~라는 설이 유력해요", "확실하지 않아요"처럼 명시. 증거가 약하면 아예 빼기.
- 유명한 민간어원은 사실로 쓰지 말 것. 쓰려면 "salary 소금 월급" 카드처럼 ‘사실은 근거가 약하다’는 반전 카드로만. 예: sincere=밀랍 없이, tip=To Insure Promptness, kangaroo=모르겠다, posh, butterfly=버터색, 'rule of thumb' 등.
- 닮았지만 남남인 단어(namae/name 같은 우연)는 좋은 소재다. 단, 정말 무관한지 확인할 것.
- 번역과 발음표기도 사실이다. 흔한 표준어로, 표기는 신중하게.

## 다양성
한 배치 안에서 이런 유형을 섞을 것:
- 유럽어끼리 같은 뿌리 (그림의 법칙 같은 소리 변화 포함)
- 한중일 한자어 공유, 한자 글자 풀이
- 외래어가 건너온 경로 (포르투갈어→일본어→한국어 등)
- 원래 뜻이 지금과 완전히 다른 단어
- 닮았지만 친척이 아닌 단어
- 한국어 사용자가 "아!" 할 연결고리 (한국에서 쓰는 외래어, 브랜드가 아닌 일상 외래어)

## 완료 보고
작업이 끝나면 마지막 메시지로만 보고: 카드 수, 새 vocab 수, 확신이 덜해서 "설"로 표기한 카드 id 목록, 뺀 아이디어 몇 개. 파일 내용 전체를 보고에 붙이지 말 것.
